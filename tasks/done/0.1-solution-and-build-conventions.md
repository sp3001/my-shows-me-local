# Step 0.1 — Solution and build conventions

Promoted from `docs/IMPLEMENTATION_PLAN.md` §Phase 0, step 0.1. Nothing exists yet; this step makes
an empty solution build with the layer graph enforceable from the first commit.

## Read

- `docs/STATE.md` — confirms nothing is built and no open question blocks Phase 0
- `docs/ARCHITECTURE.md` §1–2 — the project graph this step creates, and the dependency bans the
  `.sln` layout must make obvious
- `docs/DECISIONS.md` ADR-004 — .NET 8 pinned, one console project per job (six, not four)
- `AGENTS.md` → *Hard rules* — specifically the four that constrain this step's project references and
  packages: Domain has zero NuGet dependencies; Application must not reference EF Core / HTTP / MAUI /
  Newtonsoft; App and Infrastructure must not reference each other; and the source/mapped/user table
  split the layer graph must not make convenient to violate. Step 8.1 asserts them; this step must not
  make them awkward to assert.

Do **not** read `SCHEMA.md` or `SPEC.md` for this step. Nothing here touches data or behaviour.

## Do

1. `Shows.sln` with every project in the `ARCHITECTURE.md` §2 graph: `Shows.Domain`,
   `Shows.Application`, `Shows.Infrastructure`, `Shows.App`, `Shows.Tests`, and the six job projects
   (`Import`, `ScrapeMyShows`, `EpisodeRefresh`, `StatusRecheck`, `Enrichment`, `ImdbImport`). Four
   of the six are recurring; `Import` and `ScrapeMyShows` are one-offs (ADR-007). The total is
   deliberately not given as a number — the graph is the definition, and a count here would be a
   second owner of the same fact.
2. `Directory.Build.props` carrying the properties named in `IMPLEMENTATION_PLAN.md` step 0.1. That
   step owns the list and it is not copied here — the only thing worth restating is that the file must
   sit at the repo root so it applies to every project, including the six jobs.
3. `global.json` pinning the **.NET 8 SDK band** — without it an agent on a machine with SDK 10
   installed will build against 10 and the failure surfaces much later as a "works here" divergence.
4. `.editorconfig`.
5. `.gitignore` covering `data/`, `*.db`, `*.db-wal`, `*.db-shm`, `*.tsv.gz`, `bin/`, `obj/`,
   `log/`. The `log/` entry is not optional: `ARCHITECTURE.md` §7 puts `log/` beside `data/` under the
   base data directory, which during development resolves inside the repo, and a commit containing the
   user's watch history is the mistake this line prevents.

## Acceptance criteria

- [ ] `dotnet build Shows.sln` succeeds with **zero warnings**. Not "zero errors" — warnings are
      errors by configuration, so a build that passes with warnings means the props file did not
      apply, which is the actual thing being verified.
- [ ] `dotnet msbuild -getProperty:TargetFramework` reports `net8.0` for a class library.
- [ ] Every `.gitignore` pattern named in *Do* item 5 is present, and `git status --porcelain` stays
      empty after creating a file under `data/`.

## Constraints

- **No project references yet.** Steps 0.2–0.7 add them. An empty solution that builds is the
  deliverable; wiring the graph here means doing it twice, because 0.2 discovers what is missing.
- `Shows.App` targets `net8.0-windows10.0.19041.0` and nothing else — no `net8.0` fallback target.
- **Verified on this machine 2026-09-28:** SDKs 7.0.120, 8.0.425 and 10.0.401 are installed and
  `dotnet --version` reports **10.0.401**, so `global.json` is load-bearing rather than precautionary —
  without it this step silently builds against 10. `maui-windows` 8.0.3/8.0.100 is installed and
  visible to SDK 8, so `Shows.App` should restore without a workload install.
- If a workload install does turn out to be needed, record the exact command in the evidence, not
  "installed MAUI" — later steps need the command, not the outcome.
- Do not add a `Directory.Packages.props` central package management file unless asked — it is not in
  the plan, and adding infrastructure silently is how a step exceeds its scope.
