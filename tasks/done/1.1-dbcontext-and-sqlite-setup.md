# Step 1.1 — `ShowsDbContext` and SQLite setup

## Read
- `docs/STATE.md` — current state; 0.1–0.4/0.6–0.8 done
- `docs/SCHEMA.md §1, §1a` — conventions and the id encoding (the EF trap)
- `docs/ARCHITECTURE.md §3, §4` — Infrastructure owns EF; `DataPaths` supplies the path
- `docs/IMPLEMENTATION_PLAN.md step 1.1` — acceptance criteria

## Do
- `ShowsDbContext` in Infrastructure, `UseSqlite` with the path from `DataPaths`.
- On every connection open: `PRAGMA journal_mode=WAL`, `PRAGMA foreign_keys=ON`, `PRAGMA busy_timeout=5000`
  (a `DbConnectionInterceptor`, since foreign_keys/busy_timeout are per-connection).
- Snake-case naming convention for tables/columns.
- `ValueGenerated.None()` applied **by convention to every property** in one place, so no entity can
  opt out — the SQLite provider otherwise assumes `INTEGER PRIMARY KEY` is store-generated.
- A design-time `IDesignTimeDbContextFactory` so `dotnet ef` works without the MAUI head.

## Acceptance criteria
- [ ] Integration test creates a temp database file, opens and closes the context, asserts the file
      exists and `journal_mode` reads back as `wal`.
- [ ] The generated migration contains **no** `AUTOINCREMENT` (grep the script).
- [ ] Reflectively, no entity property has `ValueGenerated != Never`:
      `context.Model.GetEntityTypes().SelectMany(t => t.GetProperties()).Where(p => p.ValueGenerated != ValueGenerated.Never)`
      is empty. The reflection check is the one that matters.

## Constraints
- The convention must beat the SQLite provider's `OnAdd` default on `INTEGER PRIMARY KEY`. A probe
  entity with an `INTEGER` PK must come out `Never` in the built model.
- No `AUTOINCREMENT`, no store-generated keys (ADR-026/027).
