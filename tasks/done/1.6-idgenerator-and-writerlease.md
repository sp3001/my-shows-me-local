# Step 1.6 — `IdGenerator` and `WriterLease`

## Read
- `docs/SCHEMA.md §1a` — the canonical owner of the id encoding (mint expression, epoch, rollback,
  sequence exhaustion). This step builds it; it does not redefine it.
- `docs/SCHEMA.md §2` — `writer_lease` and the conditional-upsert acquire.
- `docs/DECISIONS.md ADR-026/027/028` — client-generated keys, the 64-bit layout, concurrent writers.
- `docs/IMPLEMENTATION_PLAN.md step 1.6` — acceptance criteria.

## Do
- `IdGenerator` mints `long`: `(ms - epoch) << 22 | salt << 12 | sequence`, epoch `2026-01-01T00:00:00Z`
  as a named constant. Lock the mint. Rollback ≤ 2 s keeps minting at `lastTimestamp`; > 2 s throws.
  Sequence exhaustion spins to the next ms, never wraps.
- `SqliteWriterLease` implements the conditional-upsert acquire, the heartbeat renew (returns whether
  the lease is still held — false means stop writing), and release. Both registered as singletons.
- Migration gate: `Migrate()` refuses to run while any lease is live, surfacing the job name.

## Acceptance criteria
- [x] 100,000 ids strictly increasing and positive.
- [x] Bit layout decodes to the mint instant; real-clock id decodes within seconds of `UtcNow`; layout
      sums to exactly 64 bits.
- [x] Clock rollback: 1 s keeps ids increasing, 60 s throws.
- [x] Sequence exhaustion: the 4,097th id has a later timestamp (spun, not wrapped).
- [x] Two salts in a tight loop share no id.
- [x] Lease: second acquire fails while held, succeeds after release, succeeds after expiry forced past.
- [x] Lease loss: renewal after a takeover updates zero rows (returns false).
- [x] Migration: `Migrate()` refuses under a live lease and names the job.

## Constraints
- The mint is `lock`ed — the app mints from UI and HTTP-callback threads alike.
- The lease is a singleton over the context factory, never captive to a scoped context.
- No `DateTimeOffset` comparison in a LINQ `WHERE` clause — SQLite cannot translate it (raw SQL only).
