# Step 1.5 — `TvmazeShowMapper` — the single mapped-row write path

## Read
- `docs/SPEC.md R11, R12, P2, P4` — the one mapper, the one vocabulary dictionary, fail-closed.
- `docs/SCHEMA.md §2, §2a` — the mapped tables and the rebuild drill (id immutability).
- `docs/DATA_ANALYSIS.md §8` — the Black Mirror payloads the fixtures come from. Do not re-derive them.
- `docs/DECISIONS.md ADR-023` — one mapper, never regenerates a surrogate id.
- `docs/IMPLEMENTATION_PLAN.md step 1.5` — acceptance criteria.

## Do
- `TvmazeShowMapper` writes source rows verbatim, records every `status_raw` in `tvmaze_status_seen`
  (`INSERT ... ON CONFLICT`), translates vocabulary through the one `TvmazeVocabulary` dictionary,
  upserts `tracked_show`/`season`/`episode` on natural keys, and recomputes the cached columns via
  `ShowProgress.Compute`.
- `MapShowAsync(int)` plus a `TvmazePayload` overload for callers that already fetched.

## Acceptance criteria
- [x] Black Mirror fixture: `Running` → `ShowStatus.Running`, `premiered` → 2011-12-04, runtime null +
      average 62 both preserved, `externals.imdb` → `tt2085059`.
- [x] Unseen status (`"On Hiatus"`) → `Unknown` **and** a `tvmaze_status_seen` row with `mapped_to NULL`.
- [x] Re-map a show the user marked watched → every mark survives (episode id unchanged).
- [x] Idempotent: mapping the same payload twice returns `MapResult.Unchanged`.
- [x] Never creates a `tracked_show`; never writes a user table.
- [x] Rebuild drill: re-running the mapper over every `user_show` row leaves ids and user data identical.

## Constraints
- Never writes `user_show`/`episode_watch`/`ui_season_state` (SPEC P4).
- Never regenerates a surrogate id — upsert on natural keys, delete-then-insert forbidden (SCHEMA §2a).
- `runtime`/`average_runtime` stay separate; `summary` HTML stripped only on the mapped copy.

## Deviation
The literal wipe-and-reload drill is self-defeating (cascade deletes destroy the user data it protects;
client-generated ids can't be re-derived). The sound form — re-run the mapper over every `user_show` row,
assert ids immutable and user tables byte-identical — is implemented, plus a counter-example proving
delete-then-remap orphans the watch mark. See the 2026-09-29 step 1.5 entry in `docs/LOG.md`.
