- [x] Specials never auto-marked in any branch; `has_unwatched_specials` survives.
- [x] Explicit unwatched list marks every regular before the earliest gap; a count mismatch flags review.
- [x] No-list partial watch uses the first-N heuristic and is always flagged.
- [x] `totalEpisodes = 0` promotes to `total_regular = 0`, `auto_finish_eligible = 0` (SPEC R7).
- [x] The four `source_watch_status` values map to the four categories.
- [x] `user_show` count equals `tracked_show` count (no invisible shows).
- [x] Re-running `--promote` is a no-op: nothing targeted, no watch id changes.
- [x] A `blocking` row refuses and writes nothing.
- [x] A live foreign lease refuses (exit 1); a stale foreign lease proceeds (expiry is the recovery path).
- [ ] **User runs `--promote` against the real DB** and verifies the golden numbers: show `86813` = 1
      watched regular of 33 (s01e01); category counts 78/246/16/207 from `user_show` where
      `deleted_at IS NULL`; the `total=0` show; the `needs_review` count; no `myshows_id` outside
      `staging_*`; the 13 batch-58 `started: true` shows reconcile against `episode_watch`.

## Constraints
- The Promoter is the sole writer of `user_show` and `episode_watch` during the import; the mapper
  creates neither row and never writes a user table (SPEC P4/R11).
- The backfill runs AFTER the mapper (it needs the mapped `season_number`/`episode_number`/`type`).
- Never re-mint an id; never resume a failed transaction — roll back and re-run the idempotent unit.
- `--promote` is exclusive of every other lease (ADR-028); a renewal that updates zero rows stops.
- Do NOT run `--promote` against a database that has not been backed up.
