# Steps 7.1 + 7.2 — `EpisodeRefresh` and `StatusRecheck` jobs

## Read
- `docs/STATE.md` — current state; open question 9 (untoggle out of Finished) is adjacent but not this step.
- `docs/IMPLEMENTATION_PLAN.md §Step 7.1 / §Step 7.2` — the two acceptance criteria, copied below.
- `docs/SPEC.md R8/R11/R12/R14` — soft-delete filter on every job selection; mapper is the sole mapped-row
  writer; status is an enum never a raw string; transport failure throws naming the host, never empty.
- `docs/ARCHITECTURE.md §5` — the one recompute path; jobs go through the mapper, never write mapped rows directly.
- `docs/DECISIONS.md ADR-028` — writer_lease, heartbeat, zero-rows-renewal = stop writing.

## Do
- One shared job body (`ShowRefreshJob`) — both jobs are select → fetch → map, differing only in selection
  and logging. Mode enum picks the selection.
- Selection is the shared repository query (`ListActiveExcludingStatusAsync` / `ListActiveByStatusAsync`),
  which already applies `deleted_at IS NULL` (R8) and filters on the enum (R12). EpisodeRefresh excludes
  {Ended, Canceled}; StatusRecheck selects exactly {Ended, Canceled}.
- Lease-guarded (`episode_refresh` / `status_recheck`), heartbeat renewal, zero-rows = stop. `job_run` row
  with client-minted id, `items_total`/`items_changed` measured AFTER the mapper.
- R14: a per-show `TvmazeUnavailableException` (or "TVmaze has no show N") is a per-show failure, counted,
  show left for next run — never a crash, never counted as "no change".
- StatusRecheck logs a resume (status enum transition) at Information with the show id and both values.
- Two thin job entry points (`EpisodeRefreshJob`/`StatusRecheckJob`) + the two Program.cs shells point at them.

## Acceptance criteria (copied from IMPLEMENTATION_PLAN.md)
- [ ] 7.1: run twice; second run reports `items_changed = 0`.
- [ ] 7.1: a future-dated episode added to a fixture appears in `episode` (and the Upcoming block reads it).
- [ ] 7.1: the second run leaves `episode_watch` byte-identical (assert on ids, not counts).
- [ ] 7.1: a soft-deleted fixture show is NOT fetched — assert on the request count, not row counts.
- [ ] 7.2: a fixture show whose status changes to Running is updated and becomes `auto_finish_eligible = 0`.
- [ ] 7.2: a fixture show with an unseen status string maps to `Unknown` and is not treated as ended.

## Constraints
- The job must not read a source table (source-table containment, step 8.1) — the resume is detected by
  comparing the tracked entity's enum before/after the map, not by reading `tvmaze_show.status_raw`.
- The job must not write `user_show`/`episode_watch`/`ui_season_state`, and must not regenerate a surrogate id.
- `job_run.id` is client-minted (`ValueGenerated.Never`) — a fresh `new JobRun{}` with Id=0 collides on run 2.
