## Acceptance criteria
- [ ] Manual: search "black mirror", Black Mirror appears with the Russian title as primary per SPEC R3 when a
      localized title is present (TVmaze search hits carry no `title_localized`, so the original is primary here —
      the localized-primary path is proven by the `TitleRules` unit test and the card binding).
- [ ] Manual: add to Started; the add use case returns the mapped show and writes `tracked_show` + `user_show`
      (verified by the integration test; the Started tab itself is step 5.1, so "appears in the Started tab" is a
      step 5.1 check — this step proves the add writes the rows).
- [ ] Debounce: typing does not fire a provider request per keystroke (one request per pause).
- [ ] The already-tracked marker reads `user_show` where `deleted_at IS NULL` (SPEC F2) — proven by the use-case test.

## Constraints
- No View or ViewModel may name `Shows.Infrastructure` (rule 4). VMs resolve Application use cases from a scope.
- VMs use `CommunityToolkit.Mvvm`; keep them free of `MCT`-specific leakage where cheap (ARCHITECTURE §3).
- Nothing is persisted until the user adds (R8a) — rendering results writes nothing but a transport-cache entry.
- Do NOT run `--promote`. Do NOT touch staging tables.
